Ethereum blocks, validated inside an Intel TDX trust domain. Your browser checks the proof.

A machine with no operating system under it — a unikernel written in Lean, with its own network stack — is running right now in a hardware-isolated trust domain. Hand it a chain of blocks and it re-executes every transaction and checks every state root. Its answer comes back with a quote signed by a key Intel certified, and this page verifies that signature here, in your browser, without taking this server's word for anything.

    Read this before believing it

    What this is

    • The execution half of what a block relay does to a builder's block before trusting it: decode it, execute it, and refuse it unless the state root comes out as claimed.
    • Running in a real Intel TDX trust domain, as a single EFI program: a Lean runtime, a Lean IP stack, and Jaune, an executable specification of the EVM in Lean. No Linux underneath, and no one else's C library.
    • Each answer is bound to your request and a random number your browser picked, inside a quote only that trust domain could have had made.

    What it is not

    • Not connected to any relay, builder or validator, and not affiliated with one. It checks no bid and no payment to a proposer.
    • Not validating mainnet. The whole starting state travels in the request; real blocks need a state witness, which this does not read yet.
    • Not a full attestation check. Your browser verifies Intel's signatures; it does not ask Intel whether this processor's firmware is current or a certificate revoked.
    • Not proof the measurements are the published source. For that, rebuild the image (it builds to the same bytes) and boot it on a TDX host of your own.
    • Not finished: the known shortcuts are listed in TODO.md.
    This web server is outside the trust domain and is the untrusted host in this demonstration: it carries bytes between you, the guest and Intel's quote generation service.
