Seal a transaction to the machine

The builder in the trust domain holds a key that never leaves it. A transaction sealed to that key can be read by that machine and nobody else: not this web server, not the computer the machine runs on, not whoever carries it there. This page checks that the key belongs to the image it claims to, and seals in your browser. It sends your transaction nowhere; you get the sealed bytes to hand to whoever runs the builder.

1. The machine's sealing key

Asked for with 32 random bytes made here, so the answer cannot be an old one. The quote that comes back is checked with this browser's own cryptography, up to Intel's root key.

    2. Your transaction

    A signed transaction as it goes on the wire, in hexadecimal: what a wallet gives you as the raw transaction. And the last slot it may go in a block for; after that the machine drops it.

    What this does and does not keep from others

    • The sealed bytes show how long your transaction is, and nothing else of it.
    • To build a block the machine needs proofs of the state your transaction reads. Sealed as this page seals it, the machine gets them from the computer it runs on, so that computer learns which accounts and storage slots your transaction touches, though not amounts, call data, or what it does. To keep that too, seal the proofs in with the transaction: scripts/seal-with-proofs in the repository does it, with a node of your choosing.
    • The relay the block is sent to sees the block, as with every builder.
    • If the checks above pass, the key belongs to a machine with the measurements shown on the first page. Whether those are the published source is for you to check by building it.
    • This demonstration machine is not sending blocks to relays. A transaction sealed to it is kept until its slot has passed and goes into nothing.
